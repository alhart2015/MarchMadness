# v9-B Round-Asymmetry Fix -- Design

**Date:** 2026-05-01
**Branch:** feat/v9-round-fix
**Predecessors:**
- v9 spec: `docs/superpowers/specs/2026-04-30-upset-detection-design.md`
- v9 weight-sweep spec: `docs/superpowers/specs/2026-05-01-v9-weight-sweep.md`
- v9 weight-sweep findings: `docs/notes/2026-05-01-v9-weight-sweep.md`

## Motivation

`src/train_upset_model.py` (v9-B) includes `round` (1..6 = R64..Champ)
in its 7-feature input to the stage-2 XGBoost model. Training rows
get a real `round` value derived from each played game's `DayNum`
via `src.models.matchup.day_to_round`. But at apply time,
`build_v9_pairwise` reads from `output/pairwise_v4.csv`, which has
no `DayNum` column, so the apply path hardcodes `apply_df["round"] = 0.0`
on line 299:

```python
apply_df["round"] = 0.0  # unknown at apply time -- pairwise CSV has no DayNum
```

Any tree splits the trainer learned on `round` (e.g., "if round >= 4,
predict more upsets") never fire at inference -- every apply row
sees round=0.

This bug was identified in the original v9 findings
(`docs/notes/2026-04-30-upset-detection-v9.md`, section "3. Train/apply
asymmetry on round in v9-B") and again in the weight-sweep findings
(`docs/notes/2026-05-01-v9-weight-sweep.md`). Both notes deferred the
fix until v9-B became a production-swap candidate. PR 7's marginal
winner (W_UPSET=1.0, W_MISS=0.5, +18 pts vs v8) made it that
candidate; this spec fixes the bug as the prerequisite step before
deciding whether to swap.

## Scope

**In scope.**
- A season-aware structural-walk helper that, for any season, returns
  `{(team_a, team_b): round}` -- the round at which two teams would
  meet in that season's bracket structure.
- A patch to `build_v9_pairwise` to replace the `apply_df["round"] = 0.0`
  hardcoding with a lookup against this helper.
- Regeneration of `output/pairwise_v9.csv` (default-weight production
  v9-B output) with the corrected round feature.
- Re-run of the same 15-cell weight sweep from PR 7
  (W_UPSET in {1.0, 1.25, 1.5, 1.75, 2.0} x W_MISS in {0, 0.5, 1.0})
  with the round fix applied to both regeneration AND each cell's
  `build_v9_pairwise` call. Compare the new winner against the PR 7
  winner (2688 pts) and v8 (2670 pts).
- A findings note documenting the before/after deltas and a
  swap-or-don't-swap recommendation for production.

**Out of scope.**
- Refactoring training-side code. Training rows already get
  `round` from `day_to_round(DayNum)` of the actual game, which is
  correct. Touching it risks perturbing training distributions
  needlessly.
- Hyperparameter re-tuning (XGBoost params, n_estimators, etc.) of
  the v9-B model. Same model architecture, same training data --
  only the apply-time `round` feature changes.
- Switching to a different feature set or model class (e.g., the
  unmerged v9-A 4-feature variant, ensemble work). Both are separate
  TODO items.

## Approach

### Bracket-walk helper

Add `build_pair_round_lookup(season, slots_df, seeds_df) -> dict`
to `src/train_upset_model.py` (the only consumer in this scope; if
training-side ever needs it too, can move to a shared module then):

```python
def build_pair_round_lookup(
    season: int,
    slots_df: pd.DataFrame,    # MNCAATourneySlots.csv
    seeds_df: pd.DataFrame,    # MNCAATourneySeeds.csv
) -> dict[tuple[int, int], int]:
    """For a given season, return {(team_a_id, team_b_id): round}
    where team_a_id < team_b_id and round in 1..6.
    """
```

Algorithm:

1. Filter both DataFrames to the season.
2. Build `seed_to_team: {seed_str: team_id}` from `seeds_df` (e.g.,
   `'W01' -> 1453`).
3. Build `slot_seeds: {slot_name: set[seed_str]}` by walking
   `slots_df` from R1 upward. For each row,
   `slot_seeds[slot_name] = expand(StrongSeed) | expand(WeakSeed)`,
   where `expand` recursively resolves a slot reference to its leaf
   seeds. Memoize.
4. Round of a slot is `int(slot_name[1])` (R1, R2, ..., R6).
5. Walk slots in ascending round order. For each slot, enumerate all
   pairs of seeds in `slot_seeds[slot]`. The first time a pair shows
   up, write `pair_round[seed_a, seed_b] = round`. Skip if already
   set (smaller round wins).
6. Convert to team IDs via `seed_to_team`. Drop pairs where either
   seed has no resolvable team (e.g., play-in placeholders). Store
   pairs with the canonical `team_a < team_b` ordering.

This logic mirrors the bracket walk in `src/score_chalk_brackets.py`
(specifically `chalk_winners_by_slot`) but exposes the round per
pair rather than per slot.

### Patching `build_v9_pairwise`

Current line 299:

```python
apply_df["round"] = 0.0
```

Replace with:

```python
season_round = build_pair_round_lookup(int(season), slots_df, seeds_df)
def _round_for_pair(row):
    a, b = int(row["team_a"]), int(row["team_b"])
    if a > b:
        a, b = b, a
    return float(season_round.get((a, b), 0))
apply_df["round"] = apply_df.apply(_round_for_pair, axis=1)
```

Pass `slots_df` to `build_v9_pairwise` (new required argument), and
load `MNCAATourneySlots.csv` once at the top of `main()`. Update all
existing callers (`main()`, the wrapper in `src/sweep_v9_weights.py`,
and tests).

Pairs not present in the lookup (e.g., team without a seed entry,
play-in placeholders that didn't resolve) get `round=0` -- same
behavior as before for that subset, but the typical case is now
correctly populated.

### Tests (TDD)

**Unit tests for `build_pair_round_lookup`** -- in
`tests/test_train_upset_model.py`. Use a real season's data
(MNCAATourneySlots / Seeds for, say, 2024) so the bracket structure
is canonical and verifiable:

- 1-seed vs 16-seed same region (e.g., 'W01' vs 'W16'): round = 1.
- 1-seed vs 8-seed or 9-seed same region: round = 2.
- 1-seed vs 1-seed cross-region in same F4 semifinal: round = 5.
- 1-seed vs 1-seed cross-region in opposite F4 semifinals: round = 6.
- Same-team self-pair: not in the lookup (or 0 -- behavior choice;
  document it). Self-pair never occurs in pairwise_v4 by construction.

**Unit test for `build_v9_pairwise` round-feature output** -- in the
same file:

- Run `build_v9_pairwise` on the existing fixture (2 seasons, 4
  pairs) with a real seasons' slots data. Assert
  `apply_df["round"]` -- via output CSV inspection or by capturing
  via monkeypatched `fit_upset_model` -- has values in {1, 2, 3,
  4, 5, 6}, not all 0.

**Integration / regression test (informal)** -- via the runtime
gate in `src/sweep_v9_weights.py` (carries over from PR 7). The
anchor cell `(W=1.0, M=0.0)` must still reproduce v8 within 5
brkt pts. With round now non-zero, the v9-B model will produce
slightly different probabilities, so the anchor delta may shift.
The gate band of 5 pts allows that. If the new anchor delta
exceeds 5 pts, halt and debug.

### Expected effect on the model

Hard to predict. v9-B was trained on rows with round in 1..6 but
applied with round=0. With the fix, apply-time matches train-time
for the round feature. Three plausible outcomes:

1. **Modest improvement.** If the trainer found useful round-based
   splits during training (e.g., "in late rounds, the higher seed
   is less of a favorite"), they now fire correctly at apply time.
   Sweep winner could move up by some pts.
2. **Modest regression.** If the trainer's round-based splits were
   mostly noise (xgb capacity exceeds true signal at ~3000 rows),
   firing them now hurts. Sweep winner could move down.
3. **Roughly unchanged.** If round contributes minimal signal in
   either direction, the sweep results stay close to PR 7.

The findings note will report which of these the data showed.

## Success criteria

- `pytest -v` passes (current 122 + new round-related tests).
- Anchor cell sanity gate (within 5 brkt pts of v8) holds.
- Regenerated `output/pairwise_v9.csv` contains at least 95% of rows
  with `round` in {1..6} (i.e., the structural lookup resolved most
  pairs; the remainder may be play-in placeholders).
- 15-cell sweep re-runs in well under an hour (PR 7 ran in ~5 min;
  this should be similar).
- Findings note exists with before/after table and a clear
  swap/don't-swap recommendation.

## Risks and mitigations

- **F4-rotation edge cases.** `MNCAATourneySlots.csv` is the same
  source `score_chalk_brackets.py` already uses, so any per-season
  pairing oddities (1985-era brackets, COVID 2021) are handled
  consistently with the rest of the codebase.
- **Performance.** Per-season pair lookup is O(n_pairs) ~ 64 choose 2
  = 2080 per season. Across 22 seasons that's ~46k entries -- trivial.
- **Pairwise rows for non-tournament teams.** `pairwise_v4.csv` has
  `(team_a, team_b)` for every pair the model produced a probability
  for -- many of these are theoretical, not bracket-resolved. A team
  not in `MNCAATourneySeeds.csv` for that season has no slot, so the
  pair gets round=0. This is a degradation from "fix everything" but
  matches the structural reality (these teams aren't in the bracket).
  Minimal model impact: chalk-bracket walking via
  `score_pairwise_path` only consults pairs of actually-seeded teams.
- **Sweep results inconclusive.** Possible the round fix makes no
  measurable difference. Mitigation: report negatively;
  recommendation in findings note can be "no production swap on
  this evidence." That's a valid outcome.
